# Progress report + deliverable transmittal

Two short reusable formats. Replace either with a
Government-provided template the moment one exists — theirs always wins.

---

## Part 1 — Periodic progress report

**[Contract number] — Progress Report — [period]**

**1. Status summary.** Two or three sentences. On track, or not, and
why. Lead with the honest answer; a report that always says "green" is
one nobody reads.

**2. Work completed this period**
| Deliverable / task | PWS ¶ | Due | Status | Accepted |
|---|---|---|---|---|
| | | | | |

**3. Work planned next period**

**4. Performance against QASP standards**
| Standard | Threshold | Actual | Met? |
|---|---|---|---|
| | | | |

**5. Issues, risks, and mitigations**
State problems while they are still small and cheap. A COR who learns of
a slip from you keeps trusting you; one who discovers it themselves
stops.

**6. Actions requested of the Government**
Decisions, access, information, or approvals you need, each with the
date you need it by.

**7. Personnel changes** — additions, departures, credential updates.

**8. Financial summary** — billed this period, cumulative, remaining.

**Contents:** list every file by name.

**Compliance statement:** one line confirming the deliverable meets the
PWS requirement it answers, and noting any deviation with the reason.

**QC:** reviewed by ______ on ______ per the contract QC plan.
Nothing goes to the customer without this line filled in.

**Acceptance requested by:** [date per contract]

---

### Habit
File every accepted deliverable and its metrics into
`capture/library/past_performance/` **monthly** as it happens. That
record is what makes the next bid winnable, and it cannot be
reconstructed honestly a year later.
