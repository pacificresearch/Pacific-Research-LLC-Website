# SAM.gov API credential — where it lives and when it dies

## Where it lives

**One place: the cloud environment's network secret for `api.sam.gov`.**

The network proxy attaches it to every request to that host as an
`X-Api-Key` header. Nothing else holds a copy — not the source, not a
`.env`, not an environment variable, not a GitHub secret.

`SAM_API_KEY` and `--api-key` still work and take precedence, for a
checkout running off-proxy (e.g. a local Windows machine). On the cloud
environment `SAM_API_KEY` is deliberately **unset and must stay unset**.

## When it dies

    EXPIRES: 2026-12-17

SAM.gov API keys expire and must be regenerated by a signed-in human —
there is no API that mints one. So this date is tracked here and checked
daily by `capture/check_sam_key.py`, which warns with lead time and
again every day until it is renewed.

**Update the date in this file whenever the key is regenerated.** The
checker reads it from here; a stale date makes the warning lie.

## Renewing it (about 60 seconds)

1. sam.gov → Sign In (Login.gov) → **Workspace**
2. **Account Details** → **API Key** → regenerate, copy it
3. Put it in the environment's network secret for `api.sam.gov`:
   claude.ai/code → environment settings → Network secrets →
   the `api.sam.gov` entry → replace the value
4. Edit `EXPIRES:` above to the new date, commit

Step 3 is the only place. Nothing else needs touching, and no machine
needs to be kept in sync.

## Why it is done this way

The key used to be copied into six places (committed source, a `.env`, a
shell variable, a Windows user environment, a cloud variable, a GitHub
secret). A rotation fixed some and silently missed the rest, which hid a
dead key for seven weeks and produced blank reports that read like quiet
weeks. See `capture/LEARNING_LOG.md` entries 13–16.
